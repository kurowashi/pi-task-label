# ADR 0004: 設定を変更する仕組みを追加する前に、現在の解決済み状態を確認できるようにする

- 状態: 採用
- 日付: 2026-10-03
- 対象: 全リポジトリ共通の PHILOSOPHY.md(9コピーを逐語同一に更新)

## 背景

- ADR 0003 で、設定の正をファイルとし、変更コマンドは実測した変更頻度が高い設定にだけ追加することを決めた。
- 変更の前提として、現在の状態を知る必要がある。設定ファイルだけでは、プラグインごとのマージ、既定値、環境変数、
  trust、入力値の検証などを適用した実効値が分からない場合がある。
- 表示は読み取りだけで完結する。設定を書き換える処理、未知キーの保持、設定ファイルの選択、
  同時セッション間の競合を扱わないため、変更コマンドより実装と保守の範囲が小さい。
- 表示は変更コマンドが無くても成立する。表示があれば、ユーザーはファイルを直接直せる。

## 決定

1. 設定を持つプラグインは、設定を変更する仕組みを追加する前に、ユーザーが現在の解決済み状態を pi セッション内から確認できるようにする。
2. 表示は全モードで動くユーザー向けコマンドで行い、モデル向けツールにはしない(原則1)。
3. 秘密情報はマスクし、長文は長さに要約する。
4. 設定を持たないプラグインには要求しない。

## 理由

- 読みは書きの前提である。変更するには現在の解決済み値が要る。
- 解決済み状態の表示は診断に効く。壊れた値、trust で無視された project 設定、警告の出所をユーザーが確認できる。
- 表示は引数コマンドで行う。ADR 0003 の変更コマンドと同じく全モードで動き、テストで拘束できる。
- 表示を解決済みオブジェクトから生成すれば、設定を増やしても表示の更新が要らない(pi-exa の `/exa config` が実証済み)。

## 帰結

- pi-exa / pi-reminder / pi-jev は既存の status 表示を維持し、不足するキーがあれば追加する。
- pi-task-label / pi-chat-view / pi-spawn / pi-knowledge は表示コマンドを追加する。
- 設定を持たない pi-retry / pi-plan には要求しない。
- 表示には ADR 0003 の「実測した変更頻度」条件を適用しない。

## 代替案

| 代替 | 却下理由 |
|---|---|
| 変更コマンドと表示を同時に用意する | 読みは書きの前提であり、書きの実測もない |
| 表示をモデル向けツールにする | ツール定義が毎リクエスト再送され、原則1の継続コストになる |
| 設定ファイルの中身をそのまま表示する | マージ・既定値・trust・警告が反映されず、実効値にならない |
