# ADR 0001: ラベルは保存せず、入力のたびに現在のブランチから再生成する

- 状態: 採用
- 日付: 2026-09-27
- 対象: ラベルの状態管理と `session_tree` の扱い

## 背景

- ラベル生成は「前回のラベル」を入力に使う案から始まった。ユーザーが `OK` とだけ返したとき、
  前回ラベルが文脈になるという理由だった。
- 一方でセッションは tree を持ち、分岐を移動できる。メモリ上の前回ラベルは移動前のブランチの内容であり、
  移動後は整合しない。
- 保存先の候補には `pi.appendEntry()` によるブランチ内の保存もあった。

## 決定

1. ラベルは保存しない。表示専用であり、セッションにもコンテキストにも書き込まない。
2. 生成の入力は、その時点のブランチ末尾から収集した文脈に今回のユーザー入力を加えて毎回再計算する。
3. `session_tree` ではラベルを消し、次の入力で新しいブランチから生成し直す。

## 理由

- ラベルの意味は「直近の assistant の次の一手」であり、`OK` のケースは直前の assistant の本文から
  取れる。前回ラベルは必須ではない。
- 保存すると tree の分岐とラベルの整合を取り続ける責任が生まれ、表示の価値に対して重すぎる。
  再計算なら整合は構造的に保証される。
- 前回ラベルを入力に渡す案は、誤ったラベルが入力に戻って自己強化する経路にもなる。

## 帰結

- tree を移動した直後、次の入力まではラベルが消える。古いブランチのラベルを残すより正直である。
- 生成のたびにブランチ末尾を読み直すが、既定の `assistantLookback` では対象は直近の数件なのでコストは無視できる。

## 代替案

| 代替 | 却下理由 |
|---|---|
| ブランチへ保存 | 保存・分岐整合のコードが増える |
| メモリに保持 | tree 移動後に古いラベルが残る |
| tree 移動時に即再生成 | 入力なしの重複生成になる |
