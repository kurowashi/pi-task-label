# ADR 0002: 哲学から存在理由の主張を外し、原則5をインストール＝有効化に改める

- 状態: 採用
- 日付: 2026-09-27
- 対象: 全リポジトリ共通の PHILOSOPHY.md(5コピーを逐語同一に更新)

## 背景

- 「## なぜ存在するか」は、何の存在理由か(文書・グループ・個々のプラグイン)を答えられない見出しだった。
  グループの目的は各リポジトリの DESIGN.md「何を解くか」にあり、哲学文書の領分ではない。
- 原則5「既定値は off」は実態と合わない。プラグインはインストール時に読み込まれて既定で働き、
  ビルトインのスイッチも既定は有効です(pi-reminder / pi-task-label の `enabled`、
  pi-jev の検査は設定ファイルがある場合に既定で有効)。pi-exa と pi-spawn はプラグイン単位のスイッチを持ちません。
- 「有効化」は2つの概念を指す。プラグインのロード(インストール)と、
  セッション中の機能の有効化(pi-exa の `/exa enable`、pi-reminder の `/reminder on`)です。
  原則5が定めるのは前者だけです。
- 「数値制約との関係」の冒頭の表(対象 / 記載場所 / 変更方針)は数値の話ではなく文書の役割分担であり、
  「変更の規律」の箇条書きと重複していた。

## 決定

1. `## なぜ存在するか` を `## 基準` に改め、「プラグイン群の役割」の主張を基準の定義に置き換える。
2. 採用規則の主語をグループから機能に変える(「このプラグイン群に含めません」→「採用しません」)。
3. 原則5を「インストールを有効化とし、自動的に有効になる経路を持ちません」に改める。
   セッション中の機能の有効化は対象外であり、別操作として残る。
4. 「数値制約との関係」の表を削除し、「共通哲学の変更はまれ」を「変更の規律」へ移す。

## 理由

- 哲学文書は設計を判断する基準を持ちます。目的を持つのは DESIGN.md です。
- 原則は実態と一致していなければ判断に使えません。「既定値は off」を残すと、
  既定 on のプラグインすべてが逸脱扱いになり、例外を積み上げる運用になります。
- 「有効化」を限定しないと、セッションコマンドによる機能の有効化と矛盾します。
  原則はプラグインのロードだけを定めます。
- 同じ内容を2箇所に置きません。役割分担は「変更の規律」が1箇所で持ちます。

## 帰結

- pi-task-label の `enabled: true` は原則の下で整合し、例外の記録が不要になります。
- プラグインが自動で有効になる経路は設計として不可になります。
  機能単位の有効化(設定・コマンド)は別操作として残ります。
- 「哲学でない規約(テスト運用・文書保守)の分離」は別タスクとして残ります。

## 代替案

| 代替 | 却下理由 |
|---|---|
| 原則5をそのままに pi-task-label の既定を false にする | 実態と合わない原則を残したまま、新しい例外の理由づけが要る |
| 見出しだけを `## 基準` に変える | 「プラグイン群の役割」の主張が残り、目的が2箇所に存在し続ける |
| 重複した表を残す | 判断の入口が2つになり、片方だけ更新される |
